# Android and WLED QA — 7 October 2026

Status: in progress; controller connectivity and restoration are still pending.
This covers the unreleased notification, Glance and catalog changes plus the
v1.3.2 Send fixes. No release or Pages deployment was made during QA.

## Setup

Pixel 8, Android API 37, wireless ADB; WLED 16.0.1 on an ESP32 with a 16×16
display. The original phone data and controller state, presets, configuration
and file listing were backed up before testing. Tests used local synthetic
notifications and uniquely named content. No account messages were sent.

A temporary QA entry point exercised the real app controllers and Android
bridges. Catalog tests used a local fixture server forwarded through ADB;
they do not verify the public GitHub Pages endpoint. Firmware reception was
verified through WLED's realtime status and the phone's DDP source address.
The physical panel was not visible to the tester or user.

## Fixes found during QA

1. A Send could report failure after WLED had saved its entry but lost the HTTP
   acknowledgement. Send now checks the exact unique staged filename, entry
   name, Image effect and power state before accepting an unacknowledged save.
   Regression tests cover both a persisted write and an older entry that must
   still fail. Physical retesting is pending stable controller connectivity.
2. Android can disconnect notification access before updating its permission
   setting. The native bridge now observes the committed setting directly.
   Retesting confirmed that actual Android revocation reaches Dart as access
   denied/disconnected. Retesting with an active monitor still needs the
   controller online.
3. The foreground notification's Stop path could leave a regular live animation
   running when monitoring owned the service without a tool stop callback.
   Stop now closes remaining playback/streaming after feature callbacks.
   The regression test covers monitor-only ownership; physical retesting is
   pending.
